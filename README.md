# CCTV 영상으로 택배 상자 크기 재기

컨베이어 벨트를 찍은 CCTV 영상만 보고, 지나가는 **상자의 가로·세로·높이(cm)** 를 맞히는 대회 솔루션입니다.
**최종 2위**를 했습니다.

---

## 뭐가 어려운 문제인가

사진 속 물체의 실제 크기를 알려면 보통 **카메라 정보(초점거리 등)** 가 필요합니다.
그런데 이 대회는 채점용 영상에 그 정보를 주지 않습니다. 픽셀 크기만 보고 cm를 맞혀야 합니다.

**핵심 아이디어는 "자"를 하나 찾는 것**입니다.
영상 속 컨베이어 **레일의 폭이 항상 62.3cm** 로 고정되어 있습니다.
그러면 "상자가 레일 폭의 몇 배인가"만 재면 카메라 정보 없이도 실제 cm가 나옵니다.

```
상자 크기 = 62.3cm × (상자 픽셀 / 레일 픽셀) × (깊이 보정) × (학습 보정)
```

이 한 줄이 이 프로젝트의 뼈대입니다.

---

## 어떻게 푸는가

영상 한 편이 들어오면 세 단계를 거칩니다.

**1. 상자를 찾는다** — 검출기(RF-DETR) 3개가 각각 영상을 조금씩 다르게 잘라서 봅니다.
   (벨트만 확대 / 검은 여백 제거 / 원본 그대로). 셋의 결과를 종합해 안정적으로 상자를 잡습니다.

**2. 상자를 추적한다** — 프레임을 넘나들며 같은 상자를 이어 붙여, 영상에 상자가 **몇 개** 있는지 셉니다.

**3. 크기를 잰다** — 두 방식을 섞습니다.
   - **CNN** (상자 사진의 생김새를 학습) — 20%
   - **기하 계산** (위의 "자" 공식으로 물리적으로 측정) — 80%

```
영상 ─┬─ 상자 검출 (RF-DETR ×3)
      ├─ 추적 & 개수 세기 (OC-SORT)
      └─ 크기 = CNN × 0.2  +  기하 계산 × 0.8
```

> **왜 개수가 중요한가?** 채점 방식이 상자를 부피순으로 줄 세워 비교하는데,
> 개수를 하나라도 틀리면 줄이 밀려서 **엉뚱한 상자끼리 비교**됩니다.
> 오답 영상 하나당 평균 7.9점을 잃어서, 크기만큼이나 개수 정확도가 중요합니다.

## 실행

```bash
pip install -r requirements.txt
python main.py --input {영상_폴더}      # → result.json 생성
```

학습된 모델(ONNX 15개, 총 1.4GB)이 `checkpoints/` 에 있어야 합니다.
용량이 커서 이 저장소에는 포함하지 않았습니다 — **아래 "직접 학습하기"** 로 만들 수 있습니다.

```
checkpoints/
  det_crop.onnx  det_bar.onnx  det_full.onnx    상자 검출기 3종
  f_tight_s1~4.onnx  f_rail_s1~2.onnx           크기 CNN 6개
  seg_box.onnx  belt_seg.onnx                   상자/벨트 영역 분할
  da3_metric_large.onnx                         깊이 추정 (Depth Anything V3)
  rf_long/mid/short.onnx                        기하 계산 보정 회귀기
```

## 직접 학습하기

`train/` 의 스크립트를 번호 순서대로 실행하면 위 모델들이 만들어집니다.
자세한 명령어는 [train/README.md](train/README.md) 에 있습니다.

```
01 상자 자동 라벨링  →  03 데이터셋 만들기  →  05 검출기 학습     → det_*.onnx
06 추적으로 상자 크롭 모으기 → 07 정답 크기와 매칭
08~10 크기 CNN 학습                                              → f_*.onnx
11~12 기하 특징 뽑고 보정 회귀기 학습                            → rf_*.onnx
```

라벨링은 자동으로 만든 뒤 **1500장(상자 9071개)을 사람이 직접 검수**했습니다.
참고로 **자동 라벨과 검수 라벨을 섞으면 오히려 성능이 떨어져서**(실측 확인) 검출기는 검수 라벨만 씁니다.

## 검증 — 이 프로젝트에서 제일 중요했던 부분

제출은 하루 3번뿐이라 리더보드를 실험 도구로 쓸 수 없었습니다.
게다가 나중엔 **리더보드 점수 자체를 믿을 수 없게** 됐습니다
(공개 채점 영상을 학습에 넣었더니 "외운" 점수가 나옴 — 자세한 내막은 아래).

그래서 **로컬에서 정직하게 채점하는 도구**를 만들어 유일한 판단 기준으로 삼았습니다.

```bash
python eval/cv_honest_oof.py --data datasets/size3_tight --full_gt   # 교차검증 (영상 단위)
python eval/blend_eval.py                                            # 실제 배포 구성 그대로 채점
python eval/scorer.py                                                # 공식 채점 방식 재현
```

한 가지 원칙: **모델 성분을 따로 재지 말고, 실제로 배포되는 조합 그대로 재라.**
따로 재면 좋아 보이던 게 합치면 사라지는 일을 반복해서 겪었습니다.

## 배운 것들 (요약)

전체는 [docs/findings.md](docs/findings.md) 에 정리했습니다. 핵심 셋만:

**1. 우리 한계는 "정보 부족"이지 "보정 부족"이 아니었다.**
크기를 작은 건 크게, 큰 건 작게 예측하는 편향이 있었는데, 이걸 억지로 펴면 점수가 **더 나빠졌습니다.**
이론적으로 우리 모델은 이미 "가진 정보로 낼 수 있는 최선"이었기 때문입니다.
→ 상위권과의 격차는 튜닝이 아니라 **더 나은 측정 방법**에서 나옵니다.

**2. 성분만 따로 재면 속는다.**
기하 계산을 개선해서 단독 점수가 좋아져도, CNN과 합치면 이득이 사라졌습니다.
CNN이 이미 그 정보를 갖고 있었기 때문입니다. → 항상 최종 조합으로 검증해야 합니다.

**3. 상자 개수를 놓치는 건 "작은 상자" 때문이다.**
큰 상자는 95~99% 잡는데 아주 작은 상자(50px 미만)는 66%밖에 못 잡았고,
검출기 종류를 바꿔도 똑같이 66%였습니다. → 모델 문제가 아니라 정보/데이터의 한계.

그 공개 50영상을 검출기 학습에 넣으면서 **리더보드가 "이미 본 문제"** 가 되었습니다.
(비공개 150과 별개라 규정상 문제는 없지만, 리더보드 숫자가 부풀려진 것.)

같은 50영상을 "처음 보는 조건"으로 재면 배포본 0.240 vs 새 검출기 0.280 으로 오히려 비슷하거나 약간 나빴습니다.
그래서 이후로는 리더보드를 믿지 않고 로컬 정직 채점만 신뢰했습니다.
