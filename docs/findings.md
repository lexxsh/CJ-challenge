# 실험 기록 — 무엇이 통했고 무엇이 통하지 않았나

성공한 것보다 **실패한 것과 그 이유**가 많습니다. 같은 문제를 다시 만날 사람을 위해 남깁니다.

---

## 1. 가장 큰 교훈: 나침반을 먼저 고쳐야 한다

제출 횟수가 하루 3회로 제한돼 리더보드를 A/B 도구로 쓸 수 없었습니다. 로컬 지표가 유일한 판단 근거였는데,
**그 지표가 오래 틀려 있었습니다.**

### 결함 1 — 선택 누수 (초기)

홀드아웃 13영상으로 best epoch 을 고르고, 그 홀드아웃으로 성능을 보고했습니다.
in-sample 6.25 vs out-of-sample 10.27 — **4점을 암기**하고 있었습니다.

→ 영상 단위 GroupKFold(5). outer test fold 는 학습·에폭선택 어디에도 쓰지 않고 inner val 을 따로 둡니다.

### 결함 2 — count 가 지표에서 사라짐

정직한 OOF 를 만든 뒤에도 리더보드와 1.03 어긋났습니다. 원인은 GT 생성 방식이었습니다.

```python
def gt_videos(recs):        # 매칭된 트랙에서 GT 를 만듦
    byt[(vid, track)] = r   # → 트랙이 9개면 GT 도 9개 → count 가 항상 정답
```

실제 채점은 예측·정답 중 짧은 쪽 앞에 (0,0,0) 을 패딩하므로 **미검출이 큰 벌점**입니다.
`--full_gt` 로 GT 를 `train_label.json` 의 전 물체로 놓자 OOF 11.16 → 12.06 이 되고,
**리더보드 12.19 와 격차가 0.12 로 붙었습니다.**

### 결함 3 — 성분 단독으로 판단

이게 제일 자주 속았습니다. **세 번** 같은 실수를 했습니다.

| 개입 | 성분 단독 | 배포 구성(혼합) |
|---|---|---|
| seg 줌 | 기하 10.74 → **10.54** (−0.19) | 11.394 → **11.448** (+0.05, 악화) |
| 수축 보정 | 축별 편향 절반으로 감소 | 10.77 → **11.24** (악화) |
| CNN 재학습 | — | −0.064 (노이즈) |

CNN 이 이미 갖고 있는 정보를 기하가 더 잘 잡아봐야 혼합 후에는 새 정보가 아닙니다.
→ 이후 모든 판정은 `eval/blend_eval.py` 로 **CNN+기하 혼합 + 기하 없는 트랙 CNN 폴백**까지
배포 그대로 재현해서 했습니다.

### 결함 4 — 리더보드 자체가 오염됨

Hidden Test 150영상이 최종 채점이고 공개 test 50영상은 리더보드용입니다.
우리는 공개 50의 검수 라벨을 검출기 학습에 넣었고(정당함 — hidden 과 별개),
**그 순간 리더보드가 in-sample 이 되었습니다.**

```
공개 50 count:  0.240 (미학습) → 0.100 (학습 후)
                0.14 × 7.9점/MAE = 1.11점  ≈  관측된 리더보드 개선 1.16점
```

**12.097 → 10.937 (−1.16) 은 전부 memorization 으로 설명됩니다.**
같은 50영상에서 둘 다 처음 보는 조건으로 재면 배포본 0.240 / 새 검출기 0.280 으로 오히려 근소 열세였습니다.
→ 이후 리더보드는 신호로 쓰지 않았습니다.

**노이즈 기준** (이것도 실측): 시드 std ~0.06, 50영상 count ±0.1, 90영상 count ±0.07.
**0.15 미만 차이는 읽지 않습니다.** 부트스트랩 신뢰구간으로 확인했습니다(`eval/ocsort_check.py`).

## 2. 치수(size): 정보 부족이지 편향이 아니다

구간별로 보면 편향이 뚜렷합니다. 작은 박스는 부풀리고 큰 박스는 깎습니다.

| GT long | 편향 | MAE |
|---|---|---|
| 10-22cm | **+5.15** | 5.45 |
| 22-29cm | +3.08 | 4.98 |
| 29-34cm | +0.75 | 4.53 |
| 34-41cm | −1.34 | 4.35 |
| 41-71cm | **−6.93** | 8.04 |

고칠 수 있어 보입니다. **고칠 수 없습니다.**

```
축      상관 r    수축비(예측std / GT std)
long    0.746     0.79
mid     0.739     0.76
short   0.671     0.71
```

**수축비가 상관계수와 거의 같습니다.** 회귀 감쇠 이론에서 MSE 를 최소화하는 수축계수가 정확히 r 이므로,
모델은 **주어진 신호 하에서 이미 최적**입니다. 구간별 편향은 버그가 아니라 약한 신호에 대한 올바른 헤징입니다.

실제로 펴봤더니 편향은 절반이 됐지만 점수는 나빠졌습니다.

| | scorer | long 편향 (작은/큰) |
|---|---|---|
| 보정 없음 | **10.77** | +5.15 / −6.92 |
| 분산 매칭 | 11.33 | +2.59 / −4.12 |
| 분위 매핑 | 11.24 | +2.80 / −4.05 |

**→ 캘리브레이션·재정식화 계열은 전부 사망.** 개선하려면 r 자체를 올려야 합니다.

### 신호를 얼마나 갖고 있나

| 구성 | scorer |
|---|---|
| 모든 박스에 GT 전체평균 (신호 0) | 19.140 |
| **우리 기하스택** | **10.770** |
| 영상별 GT 평균을 아는 오라클 | 16.407 |

신호 0 에서 8.37점을 벌었고, **영상 평균을 완벽히 알아도 16.4** 라는 건 이 문제의 가치가 전부
**박스별 판별**에 있다는 뜻입니다. 1등 수준(7점대)은 대략 **r ≈ 0.93** 이 필요합니다(우리 0.75).
이건 튜닝이 아니라 **추정 vs 측정**의 차이입니다.

### 측정 경로도 시도했고, 실패했습니다

DA3(Depth Anything V3) large 는 depth 뿐 아니라 **intrinsics 를 예측**합니다.
이걸로 박스 픽셀을 3D 로 역투영해 실측하면 r 을 올릴 수 있다고 봤습니다.
기존 프로브의 핸디캡(저해상도, bbox 사용)을 제거하고 **seg 마스크 + 2배 해상도**로 다시 했습니다.

```
              long     mid    short
e0 (최대축)   0.521   0.432   0.378
e1            0.502   0.583   0.463
e2 (최소축)   0.371   0.360   0.434
단순 픽셀폭   0.604   0.539   0.472    ← 3D 실측보다 낫다
현 기하스택   0.746   0.739   0.671
```

**3D 실측이 단순 픽셀 특징보다도 못했습니다.** 다만 레일 기반 절대 스케일 복원 자체는 작동했습니다
(실측 e0/e1/e2 = 41.4/28.5/13.0 vs GT 32.7/21.9/13.9 — 최소축은 거의 정확).

실패 원인: 단안 depth 의 픽셀 노이즈가 시선 방향으로 점군을 늘려 **최대 extent 가 27% 부풀고**,
보이는 것은 박스의 **껍질**이라 부분 표면에 PCA 를 걸어도 변(edge)이 나오지 않습니다.
DA3 는 "이 물체가 얼마나 먼가" 에는 충분해도 **"몇 cm 인가" 를 픽셀 단위로 재기엔 거칩니다.**

**미탐색으로 남긴 것**: 벨트 평면을 제약으로 건 oriented 3D 박스 피팅, 키포인트 코너 + PnP.

## 3. 개수(count): 작은 박스가 병목

미검출 원인을 크기별 recall 로 분해했습니다.

| GT 박스 크기 | recall |
|---|---|
| **0-50px** | **66%** |
| 50-70px | 87% |
| 70-90px | 95% |
| 90-120px | 96% |
| 160px+ | 99% |

**YOLO26m 과 RF-DETR 이 0-50px 에서 똑같이 66%** 였습니다(65.8 vs 66.0).
아키텍처가 아니라 학습 신호/정보의 문제라는 뜻입니다.

시도한 것과 결과 (fold1 val, GT 1787):

| 개입 | 0-50px | 전체 |
|---|---|---|
| baseline (imgsz 1280) | 66.2% | 87.9% |
| 작은 박스 손실 가중 | 69.3% | 88.6% |
| **imgsz 1536** | 69.7% | **90.4%** |
| imgsz 1536 + 가중 | **70.0%** | **90.5%** |
| imgsz 1792 | 63.1% ↓ | 89.1% ↓ |

**해상도에는 최적점이 있습니다.** 1792 는 baseline 보다도 나빴습니다.
그리고 **0-50px 은 66→70% 에서 완전히 막혔습니다.** 무엇을 해도 뚫리지 않았습니다.

전부 실패한 대안들:

| 시도 | count MAE |
|---|---|
| **RF-DETR + OC-SORT (채택)** | **0.233** |
| 프레임당 최대 검출 | 0.530 |
| 트랙 병합 규칙 | 0.200~1.490 |
| det + seg 융합 | 0.990 |
| RF-DETR + YOLO 앙상블 | 0.333 (악화) |
| count 직접 회귀 (CNN/ViT) | 실패 |
| OC-SORT 재튜닝 (12축 스윕) | 전부 노이즈 범위 |

## 4. 데이터: 양보다 일관성

자동 라벨 3244장 + 사람 검수 1500장을 **합치면 더 좋아질 것**으로 봤습니다. 반대였습니다.

| 학습 데이터 | test 50 count MAE |
|---|---|
| 자동 라벨만 (2867장) | **0.240** |
| 검수 라벨만 (1500장) | 0.280 |
| **둘을 합침 (3867장)** | **0.520** ← 각각보다 2배 나쁨 |

데이터를 늘려서 나빠질 수는 없습니다. **두 라벨의 기준이 달라 모델이 상충하는 지시를 받은 것**입니다.
양이 아니라 일관성 문제였습니다.

**부수 발견**: 프레임 홀드아웃(`det/val`)은 count 를 전혀 예측하지 못했습니다.
합친 데이터가 거기서는 AP 0.951 → 0.969 로 **좋아 보였지만** test 50 에서는 0.240 → 0.520 이었습니다.
같은 영상의 다른 프레임은 사실상 같은 데이터입니다 — **홀드아웃은 반드시 영상 단위로.**

## 5. 통한 것

정직하게 세어보면 많지 않습니다.

1. **기하스택 도입** — 12.187 → 12.097. 레일 비율 × depth 비율 정식화로 intrinsic 없이 스케일 복원
2. **정직한 OOF 하네스** — 점수를 직접 올리진 않았지만, 이후 모든 판단의 근거가 됐습니다
3. **ep8 + 시드 평균 + tight/rail 2뷰** — 과적합 제거 (ep40 단일 12.250 → 11.16)
4. **영상 단위 fold 통일** — 검출기·치수·평가가 같은 분리를 공유

그리고 **통하지 않은 것**: 해상도 상향(RF-DETR), 검출기 앙상블, 검출기 교체, size 재학습,
수축 보정, ratio 재정식화, 스태킹, DA3 역투영, count 회귀, 마스크 기반 count, 멀티뷰, alpha 재조정.
